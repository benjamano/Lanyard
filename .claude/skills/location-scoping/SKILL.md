# Location scoping — narrower than it looks

`ICurrentLocationContext` (impl: `CurrentLocationContextService`) is injected globally as `_currentLocationContext` in `_Imports.razor`, alongside `_companyLocationService` (`ICompanyLocationService`). Its `GetScopeAsync()` reads the authenticated user's `LocationClaimTypes.LocationId` claim (set at login) and resolves a `LocationScope(IsAdmin, LocationId, CompanyId, LocationDisplayName)`. It's scoped per circuit and memoises the resolved scope for up to a minute (keyed on the role/location claims), and `IsAdmin` short-circuits every check, so admins bypass location restriction entirely. It also carries `IsManager`, so services can enforce "Admin, or Manager at this location" themselves.

**Company tenancy and location scoping are two different things.**

- **Company tenancy is global.** Every `ICompanyOwned` entity (and its children) gets an EF query filter in `ApplicationDbContext` driven by `TenantContext` (`Services/Tenancy/TenantContext.cs`): a signed-in user only sees their own company's rows. A caller with **nobody signed in** (kiosk pages, anonymous pages, hosted services) is the **system** tenant and is **unfiltered** — it sees every company. `Location` and `UserLocationMembership` are not filtered at all, so join through `Location.CompanyId` yourself (see `SchedulingAccess.CanManageUserAsync`).
- **Location scoping is opt-in.** `LocationScope` is threaded through the Training/Course module (`CourseService`, `TrainingAnalyticsService`, `CourseAssignmentService`, `CourseRecurrenceHostedService`), Scheduling (`SchedulingAccess`, rota/time-off services) and `ComplianceService`. Other models — `Client`, `Zone`, `AutomationRule`, `Dashboard`, etc. — have no location concept; don't assume they're location-filtered.
- Anything reachable from an anonymous page (e.g. a dashboard widget shown on a kiosk) must refuse system callers itself — `ComplianceService` checks `ITenantContext.IsSystem` before querying.

## Coverage within Course itself

Every mutating/reading method in `src/Lanyard.Server/LanyardServices/Services/Training/CourseService.cs` now takes and checks `LocationScope`: `GetCoursesAsync`, `GetCourseAsync`, `SaveCourseAsync`, `DeleteCourseAsync`, `ReorderSectionsAsync`, `ReorderQuestionsAsync`, `SaveSectionAsync`, `DeleteSectionAsync`, `SaveQuestionAsync`, `DeleteQuestionAsync`. The check is always the same shape: `if (!scope.IsAdmin && course.LocationId != scope.LocationId) return Result<T>.Fail("You do not have access to this course.");` — for the section/question methods, the parent course is loaded (via `.Include(x => x.Course)` on the delete paths, or a direct `Courses` lookup on the save paths) specifically to run this check, since sections/questions don't carry their own `LocationId`.

**Fixed (2026-08-13):** `SaveSectionAsync`, `DeleteSectionAsync`, `SaveQuestionAsync`, and `DeleteQuestionAsync` previously took no `LocationScope` at all — a non-admin who had (or could guess/reuse) a section or question GUID belonging to a *different* location's course could edit or delete it, bypassing the location boundary enforced everywhere else in the service. `CourseEditor.razor`'s four call sites (`SaveSelectedSectionAsync`, `DeleteSelectedSectionAsync`, `SaveSelectedQuestionAsync`, `DeleteSelectedQuestionAsync`) now resolve the current scope via the existing `ResolveScopeAsync()` helper and pass it through, the same way `SaveCourseMetaAsync`/`LoadCourseAsync` already did. Tests: `CourseService_SaveSection_RejectsWhenScopeDoesNotOwnCourse`, `CourseService_DeleteSection_RejectsWhenScopeDoesNotOwnCourse`, `CourseService_SaveQuestion_RejectsWhenScopeDoesNotOwnCourse`, `CourseService_DeleteQuestion_RejectsWhenScopeDoesNotOwnCourse` in `CourseServiceTests.cs` cover the cross-location-rejection case; all pre-existing tests were updated to pass `AdminScope` and still pass.

**If you add a new section/question-level method to `CourseService`**, follow this same pattern — load the parent course, check `LocationScope` against it — rather than assuming the type itself is somehow already scoped.
